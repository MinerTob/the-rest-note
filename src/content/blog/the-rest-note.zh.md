2026 年 9 月 19 日，The Rest Note 正式上线。

写下这句话的时候，其实有一点奇妙。

在它真正能通过一个网址被打开以前，它在很长一段时间里都只是我电脑里的一个文件夹、一堆 `.astro`、`.ts` 和 `.css` 文件，以及不知道多少次"这个地方还是不对，再改一下"。

现在，它终于变成了一个真正存在于互联网上的地方。

## 从一个"个人主页"开始

最开始，我只是想做一个属于自己的个人网站。

但"个人主页"这个词总让我觉得少了点什么。如果只是把名字、简介、兴趣、联系方式和几篇文章排列整齐，那它更像一张放在互联网上的电子名片。

我不太想做这样的东西。

我希望有人打开它的时候，不需要带着"我要获取什么信息"的目的。

可以看看文章，可以听听音乐，可以碰几下琴键，也可以什么都不做。

于是后来，我给它取了一个名字：

The Rest Note。

Rest 可以是休息，也可以是音乐里的休止符。

一首曲子不可能从头到尾塞满音符。恰恰是那些没有声音的地方，让前后的旋律有了呼吸。

我想，这个网站大概也是这样。

在生活的旋律之间，留一拍安静给自己。

## 我用了什么做它

The Rest Note 的主体使用 Astro 7 构建，语言是 TypeScript，样式基本全部由原生 CSS 完成。

我没有使用 React、Vue 或 Svelte，也没有使用 Tailwind。整个网站最终会被构建成静态页面，所以没有数据库，也没有真正意义上的后端。

但"静态网站"并不意味着它只能静静地待在那里。

The Rest Note 里用了 Web Audio API 来处理音乐和钢琴声音，用 Web MIDI API 连接真实 MIDI 键盘；About 页那些会落下来、碰撞、被拖动甚至被手机摇晃影响的标签，则交给了 Matter.js。

博客和 Lab 使用 Astro Content Collections 管理内容，网站同时提供中文和英文版本。音频等较大的资源通过 Git LFS 管理。

于是现在的技术栈大概可以写成：

**Astro 7 + TypeScript + Native CSS + Web Audio API + Web MIDI API + Matter.js + Git LFS**

听起来已经不像我最开始说的：

"我就做个个人博客。"

## 一台藏在网页里的钢琴

音乐大概是这个网站里最不像"装饰"的东西。

Lab 里有一台 25 键 MiniLab。

它可以用鼠标点，可以触摸，可以用电脑键盘，也可以直接连接真实的 MIDI 键盘。

我还偷偷往里面塞了一些机关。

有些旋律不是菜单里的按钮，也不会直接告诉访客"点击这里触发彩蛋"。它们需要真的在琴键上被弹出来。

当正确的音符依次出现以后，网站会改变主题，音乐也会随之变化。

我很喜欢这种设计。

因为它不像传统网页那样不断告诉你：

这里可以点。

那里还有一个功能。

有些东西，本来就应该留给愿意探索的人自己发现。

## 88 个琴键，以及一点关于我

About 页是我最喜欢、同时也是折腾最久的部分之一。

页面里有完整的 88 键钢琴，上方会播放一段 MIDI 夜曲。随着音乐继续，一个个代表我的标签会从上方出现，然后按照物理规律掉下来。

音乐、民航、摄影、天文、技术……

还有直白、坚持、善于分析。

它们会碰撞，会弹起来一点，会落在不同的位置，也可以被拖动。

我没有把 About 做成传统的：

姓名：
年龄：
爱好：
自我介绍：

因为现实中的一个人本来也不是这样被几个字段拼出来的。

我更喜欢让这些东西随着音乐一点点出现。

就像认识一个人一样。

你不会在第一秒知道全部。

## 然后 Bug 开始教育我

真正开始做以后，我才发现"让它能运行"和"让一个第一次访问的人正常使用"完全是两件事。

有一次，我清掉浏览器缓存，模拟一个真正第一次来到网站的访客。

然后我按下琴键。

没反应。

原因很简单：钢琴采样还没有下载完成，而当时的代码在找不到对应采样时直接停止播放。

对开发者来说，我知道"它正在加载"。

但访客不知道。

他只会觉得：

这东西坏了。

我最开始甚至考虑过做一个加载页面，把所有音频下载完以后才允许进入网站。

后来想想，这其实是在让所有访客为一个技术问题买单。

最后我换了一种方案：

采样还没准备好时，先让轻量的合成器负责发声；真正的钢琴采样加载完成以后，再自然地接管声音。

于是，即使是第一次打开网站，第一下琴键也应该有声音。

这件事让我记住了一个很简单的道理：

用户不需要知道你的代码为什么没有准备好。

他只需要知道，自己刚刚按下去的那个东西有没有回应他。

## Safari，以及一些只有真机才知道的事情

然后轮到 iPhone 教育我。

浏览器的自动播放限制、AudioContext 的解锁、运动与方向权限、Safari 恢复滚动位置的方式……

有些问题在电脑上测试几十遍都不会出现，到了手机上就突然冒出来。

About 页的 MIDI 曾经出现过一种很离谱的情况：

第一次进入没有声音。

刷新一次，还是不一定有。

再刷新一下 ——

好了。

后来才发现，音频解锁原本被设计成"一次性的尝试"。偏偏 iPhone 第一次交互的时候还可能同时弹出"运动与方向"权限请求，于是那一次珍贵的用户手势就可能没有成功完成音频解锁。

解决办法最后不是让用户刷新。

而是让程序学会：

第一次没成功，那下一次交互就再试。

类似的问题还有很多。

Safari 会在页面遮罩消失以后偷偷恢复之前的滚动位置，于是我甚至不得不在进入网站以后分几个时间点把页面重新拉回顶部。

听起来很笨。

但它真的有用。

开发有时候就是这样。

你以为自己在研究优雅的架构，最后却在和浏览器进行某种非常原始的心理博弈。

## 它终于从 localhost 里走出来了

开发过程中，我看过太多次：

`localhost:4321`

它在那里运行的时候，我知道所有按钮在哪里，也知道所有彩蛋怎么触发。

但那终究只是我的电脑。

直到今天，我把最后的一些问题处理掉，完成构建，推送仓库，部署，然后第一次在一个真正公开的网址里看到 The Rest Note。

那一刻的感觉和"项目成功运行"还是不太一样。

因为从这一刻开始，它不再只是开发环境里的作品。

别人真的可以走进来了。

他们可能只停留几十秒。

可能读一篇文章。

可能不知道 MiniLab 里藏着什么。

可能在 About 页听一会儿夜曲。

也可能什么都不做，只是看两眼然后关掉网页。

我觉得都可以。

因为我本来就没打算把这里做成一个必须完成什么任务的地方。

## 第一小节

The Rest Note 当然还没有"完成"。

博客里现在没有多少文章，Lab 以后还会继续增加东西，设计也一定会继续变化。

但我现在反而不太想说：

"等全部做好以后再正式开始。"

因为一个真正属于自己的地方，本来就不应该存在所谓的最终版本。

它会跟着我一起变化。

今天我可能在这里写代码，明天可能写音乐，之后也许会记录一次旅行、一张照片、一架偶然遇见的飞机，或者某一天突然想到的一件小事。

很多年以后再回头看，我甚至可能会觉得现在的代码很幼稚，设计也有很多不成熟的地方。

但至少我会知道：

2026 年 9 月 19 日，我真的把它做出来了。

从最开始的一句"我想做一个自己的博客"，到几万行代码、一次次推倒重来、手机真机测试、音频加载、MIDI、玻璃材质、物理效果，再到最终部署。

它终于从我电脑里的文件夹，变成了互联网上一个很小的角落。

所以，这篇文章就当作 The Rest Note 的第一篇开发日记。

也是它的第一小节。

下一小节写什么，现在还不知道。

没关系。

休止符之后，音乐总会继续。
